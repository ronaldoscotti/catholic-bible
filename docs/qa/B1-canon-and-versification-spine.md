## The export runs twice and produces the same bytes

```
$ ./scripts/export-spine.py --source ~/…/meu-feed-catolico-api
$ cp -R src/catholic_bible/data /tmp/data-first
$ ./scripts/export-spine.py --source ~/…/meu-feed-catolico-api
$ diff -r /tmp/data-first src/catholic_bible/data
BYTE IDENTICAL on rerun
```

Provenance records the source commit date rather than the run date, which is
what makes that hold. An export timestamp would make two runs at the same
source commit differ, and the record exists to say which data this is.

## The integrity test fails on a mutation

A checksum test that never fires is decoration, so it was made to fire. Flipped
one verse count in `versification.json` from 31 to 32.

```
$ uv run pytest tests/canon -q
FAILED tests/canon/test_provenance.py::test_every_data_file_matches_its_recorded_checksum
1 failed, 2 passed
```

Re-exported and it went green. This proves integrity and not authorship. The
data and its hash are committed together here, so anyone editing a verse
recomputes both. B2 owns the job that catches that.

## What was exercised by hand

The mapping function and the parser were driven directly, outside the tests,
while the orphan report was being generated. That is where the two defects
below came from, and neither would have surfaced from reading the diff.

## Defects found and fixed during QA

**The org sweep manufactured orphans.** The report was first generated by
running every scheme over the Vulgate coordinate space, because that is what
the scheme table declares. `org` keeps Susanna and Bel as separate books, so
asking it about Daniel 13 produced orphans no `org` source could ever emit. The
`org` domain is now the image of the Vulgate space under the table.

**Inverting the table hijacked good addresses.** `org` Daniel 1:1 came back as
`no_counterpart`, which was obviously wrong for the first verse of a book the
canon has. The table carries source versifications beyond the Vulgate, `DAG` for
Greek Daniel among them, so the inverse handed Daniel 1:1 an origin the canon
does not have. All 251 addresses of Daniel orphaned. An address already on the
spine is no longer traded for one that is not.

**Reading a spine address back produced plausible wrong answers.** Sixty two
addresses came back as a neighbouring or unrelated verse rather than as nothing.
The reverse direction now maps its own candidate forward again and returns it
only if it lands where it started.
